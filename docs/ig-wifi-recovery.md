# 그랜저 IG Wi-Fi 초기화 제한 복구 시험판

브랜치: `fix/ig-wifi-sdio-recovery` / Korea Projection **1.7.2.2**.

이 시험판은 Wi-Fi 드라이버가 로드된 채 펌웨어 초기화에 실패하고 `wlan0`가 없는 경우에 한해 순정 초기화를 다시 시도합니다. **하드웨어 수리, SDIO 통신 오류 해소, 모든 그랜저에서의 동작을 보장하지 않습니다. 차량 실기 검증 전입니다.**

K3 TBT 시험판과 분리해 원래 1.7.2를 바탕으로 만들었습니다. 원래 서명된 상태 앱·BusyBox·HMG-API 무선 모드 2.4.0을 그대로 유지하며, 다른 차량의 드라이버나 펌웨어를 가져오지 않습니다.

## 공개 자료에서 확인한 것

- [#55: 2020 그랜저 하이브리드](https://github.com/StopDragon/korea-projection/issues/55): 관리자는 두 부팅 모두 칩 인식 이후 펌웨어 전송에 실패하고 드라이버가 로드된 상태로 남았다고 설명했습니다. Wi-Fi 잠금을 풀어도 같았다고 합니다. 원본 첨부는 개인정보 때문에 내려가 있으므로 본 작업에서 원본 로그를 직접 검증한 것은 아닙니다.
- [#52: IGPE21 사례](https://github.com/StopDragon/korea-projection/issues/52): 관리자는 재초기화 3회 모두 동일 지점에서 실패했다고 설명했습니다. 재시도만으로 해결되지 않는 차도 있다는 근거입니다. 부품/드라이버 중 원인은 미확정입니다.
- [#72: IGPEHEV 차종별 제보](https://github.com/StopDragon/korea-projection/issues/72): 같은 제품 코드·펌웨어에서 정상 연결 사례도 있습니다. 모델명만으로 하드웨어 고장이나 동일 Wi-Fi 칩이라고 결론 낼 수 없습니다.
- [공개 진단 USB](https://github.com/StopDragon/korea-projection/releases/download/wlan0-diag-2026-11-08/kp-wlan0-diag-usb.zip): SHA-256 `a92dc6222a1a9531bb68e9380c61e956997d7a263b9e1114143fb70f290b09a5`를 확인했습니다. 이 도구의 부팅 4분 후, 실패 근거가 있는 미사용 모듈만 내려 순정 HAL로 다시 올리는 절차를 참고했습니다.
- 공개 Korea Projection main 스냅샷: `824f9895cd7534ec11585b16f7f443bc7346024b`. 이 스냅샷과 진단 도구를 조사했습니다. 대화에서 언급된 다른 미공개 버전이나 차량의 커널 소스를 검증한 것은 아닙니다.
- [Android 4.4 계열 참고 구현](https://github.com/LineageOS/android_hardware_libhardware_legacy/blob/cm-11.0/wifi/wifi.c): 드라이버 상태 속성과 `/proc/modules`를 확인하는 구조가 있습니다. 해당 차량의 순정 HAL과 동일하다는 근거로 사용하지 않습니다.

외부 검색 사이트와 일부 첨부에 접근 제한이 있어 인터넷의 모든 정보를 확인한 것은 아닙니다. Wi-Fi 칩 리비전, AVN 부품 번호, 차량별 펌웨어/NVRAM 호환성은 확인하지 못했습니다.

## 동작 조건과 보완한 오류

자동 복구는 **`IGPEHEV.KOR.*.260902`, `IGPE21.KOR.*.260902`**에서만 실행됩니다.

1. 다른 Wi-Fi 인터페이스, AP, supplicant, DHCP, CarPlay 연결, 충돌 패키지가 없을 때만 진행합니다. `usbwifi.hotspot`이 있으면 건너뜁니다.
2. `bcmdhd` 또는 `dhd`가 **하나만**, 참조 수 **0**, 상태 **Live**일 때만 후보로 삼습니다. 사용 중인 다른 행을 놓치고 빈 모듈을 고르지 않습니다.
3. 이번 커널 로그에 펌웨어 초기화 실패 근거가 있어야 합니다. 로그를 읽지 못하거나 실패 근거가 없으면 모듈을 내리지 않습니다.
4. 부팅 뒤 최소 **4분**을 기다리고, Wi-Fi 설정 값이 정확히 0/1일 때만 시작합니다.
5. 먼저 원인 기록과 복구 진행 상태를 보존합니다. 정상 복구가 끝나지 않은 상태로 서비스/인포가 다시 시작되면 자동 재시도하지 않습니다.
6. 순정 Wi-Fi 끄기 → 꺼짐 확인 → 인터페이스·모듈 사용량 재확인 → 미사용 모듈 해제 → 순정 Wi-Fi 켜기 순서입니다. HAL이 이미 모듈을 내렸으면 실패로 보지 않고 다시 켭니다. **강제 rmmod, 직접 insmod, 칩 펌웨어 교체, 자동 재부팅은 하지 않습니다.**
7. 한 회차에서 30초를 관찰하고 마지막에 `wlan0`가 3회 연속 보여야 장치 복구로 판단합니다. 순간적으로만 나타났다가 꺼진 장치를 성공으로 보지 않습니다. 핫스팟·DHCP 성공은 별도로 확인합니다.
8. 부팅당 최대 3회, 연속 실패 부팅은 최대 2회입니다. 명령이 15초 안에 끝나지 않으면 추가 HAL 작업 없이 차단합니다. 커널에서 멈춘 작업을 사용자 공간에서 강제로 끝낼 수 있다는 뜻은 아닙니다.
9. 실패 시 알고 있는 원래 Wi-Fi 설정(0/1)을 복원하려고 시도합니다. 값이 불명확하면 처음부터 작업하지 않습니다. 복원도 끝나지 않으면 자동 시도를 차단합니다.
10. 복구 중에는 핫스팟 시작이 동시에 실행되지 않게 합니다. 설치용 백그라운드 작업이 종료되면 자신이 시작한 복구 명령도 취소합니다. 실제 AP·DHCP 없이 '무선 카플레이 준비됨'으로 완료하지 않습니다.

회복 중 Bluetooth·유선 CarPlay가 잠깐 끊기거나, 기존 진단 도구에서 보고된 것처럼 인포가 재시작될 가능성은 남아 있습니다. 정차 상태에서 시험합니다. 정상 K3 등 비대상 차량에는 복구가 실행되지 않습니다.

## 전체 USB 설치

[전체 시험판 ZIP](../test-builds/ig-wifi/korea-projection-1.7.2.2-usb.zip)을 풀어 FAT32 USB 맨 위에 내용물을 복사합니다. 안쪽 `packages/korea.projection.zip`은 풀지 않습니다.

현재 원래 Korea Projection 1.7.2를 사용한다면 NEMESIS의 일반 업데이트 방식으로 설치합니다. **HMG-API 모드를 따로 설치하거나 삭제할 필요가 없습니다.** 무선 모드와 상태 앱은 원래 서명을 유지합니다.

K3 TBT 시험판처럼 다른 서명의 무선 모드를 사용 중이라면 이 파일로 바로 전환하지 말고 해당 시험판의 원복 절차로 원래 1.7.2 상태를 먼저 복원합니다. 본 시험판에는 K3 TBT 변경이 없습니다.

설치 후 인포를 NEMESIS로 재부팅합니다. 시동 OFF/ON만으로 대신하지 않습니다. 부팅 4분 이후 복구가 시작될 수 있고, 서비스 응답과 재시도에 따라 몇 분 더 걸립니다. 그동안 Wi-Fi 설정을 조작하거나 다른 진단 도구를 동시에 실행하지 않습니다.

장치가 복구되면 기존 패키지가 AP·DHCP를 시작합니다. Launch에서 `wlan0`, 핫스팟, DHCP와 실제 CarPlay 연결을 함께 확인합니다. `recovered` 기록만으로 CarPlay 연결까지 성공했다고 판단하지 않습니다.

## 중단, 재시도 허용, 원복

- 즉시 중단: USB 맨 위에 **`kp-ig-wifi-off`**라는 빈 파일을 두면 이후 복구 단계가 중단/보류됩니다. 이미 커널에서 실행 중인 작업을 즉시 중지시키는 기능은 아닙니다.
- 계속 비활성화: 그 파일을 둔 상태에서 이 패키지를 설치하면 설정이 유지됩니다.
- 다시 활성화: `kp-ig-wifi-off`를 치우고 USB 맨 위에 **`kp-ig-wifi-on`**을 둔 상태에서 재설치합니다.
- 중단된 작업 또는 2회 실패로 차단된 상태를 재설정하려면 **`kp-ig-wifi-reset`**을 둔 상태에서 재설치합니다. 단순히 USB를 꽂거나 부팅하는 것으로 차단 기록을 지우지 않습니다. 원인 자료를 먼저 저장한 뒤 필요한 경우에만 사용합니다.
- 전체 원복: NEMESIS에서 시험판 Korea Projection 삭제 → 인포 재부팅 → [원래 1.7.2 전체 USB](../test-builds/ig-wifi/korea-projection-1.7.2-original-usb.zip) 설치 → 기존 자동 설정 대기 → 인포 재부팅.

USB의 `recovery-controls` 폴더에 빈 제어 파일을 넣었습니다. 이 폴더 안에서는 작동하지 않으며, 원하는 파일 하나를 USB 맨 위로 복사해서 사용합니다. 기본 설치에는 off/on/reset이 적용되지 않습니다.

## 결과 자료

복구 직후, 재부팅하기 전에 USB를 꽂고 Launch로 파일을 저장합니다. `KoreaProjection-report`의 공개용 3개 파일만 첨부합니다. 커널 원본·명령 원본은 공개 로그에 넣지 않습니다.

`3-log.txt`에는 다음 구간이 추가됩니다.

- `ig-wifi-recovery.txt`: 단계·중단 이유·시도 횟수·SDIO vendor/device/class. MAC·고유 시리얼은 수집하지 않습니다.
- `ig-wifi-before.txt`, `ig-wifi-after.txt`: 기존 개인정보 가리기를 적용한 초기화 전후 진단.
- `ig-wifi-recovery.state`: 부팅 ID, 상태, 연속 실패 부팅 수, 시도 횟수. `running`이 남았으면 다음 시도를 차단합니다.

칩이 계속 응답하지 않으면 '하드웨어 고장 확정'으로 안내하지 않습니다. 펌웨어/NVRAM 호환성, 전원·리셋, 드라이버 자체 문제는 추가 자료로 구분해야 합니다.

## 재빌드 및 검증

```sh
bash tests/ig-wifi-recovery-test.sh
bash tests/ig-wifi-command-timeout-test.sh
bash scripts/build-ig-test-usb.sh /outside/repo/output
```

빌더는 공식 1.7.2 릴리스 전체 ZIP의 SHA-256을 확인하고 원래 앱·BusyBox·라이선스·서명된 무선 모드를 보존합니다. 출력 버전, 모드 MD5, 모드 서명, 각 서명 파일, ZIP 무결성과 시나리오 테스트를 확인합니다. 설치 검증은 모의 플랫폼이며 실제 SDIO 장치를 구동한 것은 아닙니다.

검증 결과: 격리된 42개 복구 시나리오를 Bash와 Android 계열 mksh에서 각각 통과했고, 실제 자식 프로세스의 성공·실패·시간 제한 처리를 확인했습니다. 기존 전체 stub 테스트에는 누락된 비공개 스크립트·릴리스 전용 파일과 Linux/macOS 도구 차이로 인한 실패가 남아 있어 전체 통과로 보고하지 않습니다. 차량 설치·SDIO 실기 검증은 수행하지 않았습니다.
